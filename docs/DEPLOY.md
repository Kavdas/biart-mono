# Замена сайта на biart.kz

Как выложить новый сайт вместо того, что сейчас работает на `https://biart.kz/ru/`.
Для разработчика. Делать по порядку, не пропуская проверки.

---

## Что сейчас стоит на домене

Проверено 23.09.2026:

| | |
|---|---|
| Движок | WordPress 7.1.2 |
| Сервер | nginx, панель **Plesk** (`x-powered-by: PleskLin`) |
| Языки | префиксы `/ru/` и `/kk/`, корень `/` отдаёт 301 на `/ru/` |
| Плагины (видны снаружи) | Yoast SEO (`/sitemap_index.xml`), Google Site Kit |

Страницы старого сайта:

```
/ru/                                    /kk/
/ru/politika-konfidenczialnosti/        /kk/politika-konfidenczialnosti/
/ru/dogovor-publichnoj-oferty/          /kk/dogovor-publichnoj-oferty/
/ru/dogovor-oferty-sertifikata/         /kk/dogovor-oferty-sertifikata/
+ демо-запись «привет-мир»
```

Новый сайт устроен иначе — без языковых плагинов, вторая версия отдельной страницей:

```
/                                 главная (RU)
/kz/                              главная (KZ)
/dogovor-publichnoj-oferty/
/privacy-policy/
/dogovor-oferty-sertifikata/
```

Отсюда главное следствие: **адреса меняются, нужны 301-редиректы** (раздел 7),
иначе ссылки из поиска, мессенджеров и визиток будут упираться в 404.

---

## 1. Перед началом

- [ ] Доступ в Plesk (или к хостеру) — нужен для бэкапа, SSL и nginx-директив.
- [ ] Доступ в админку старого сайта.
- [ ] Доступ к DNS домена — на случай отката.
- [ ] На хостинге **PHP 8.1+** (в теме `Requires PHP: 8.1`). Plesk → Hosting Settings → PHP version.
- [ ] Свободное место: слепок сайта весит около 60 МБ.
- [ ] Выбрано время: лучше вечер буднего дня, не перед набором групп.

**Рекомендуется:** сначала развернуть на поддомене `new.biart.kz`, прогнать раздел 8,
и только потом заменять основной сайт. Это стоит лишний час и снимает почти весь риск.

---

## 2. Бэкап старого сайта — обязательно

Два независимых бэкапа, потому что откатываться придётся именно с них.

**Бэкап 1 — средствами Plesk.**
Plesk → Websites & Domains → biart.kz → **Backup Manager** → Back Up →
отметить *Configuration, Mail, User files and databases* → Back up.
Дождаться завершения, **скачать файл к себе на диск**.

**Бэкап 2 — All-in-One WP Migration.**
В админке старого сайта: Плагины → Добавить новый → *All-in-One WP Migration* →
Установить → Активировать. Затем All-in-One WP Migration → **Export** → Export to → File →
дождаться и скачать `.wpress`.

- [ ] Оба файла лежат локально и открываются.

Запишите отдельно: логин администратора старого сайта, список плагинов
(Плагины → Установленные), и есть ли подключения Google (Site Kit → Settings).

---

## 3. Собрать слепок нового сайта

Локально, в проекте:

```bash
npm run start
npm run setup
npm run seed
```

Открыть `http://localhost:8888/` и бегло проверить: главная, `/kz/`, три юридические
страницы, карусель листается.

Затем в админке `http://localhost:8888/wp-admin/` (admin / password):
All-in-One WP Migration → Export → **Export to → File** → скачать `.wpress`.

> Файл вберёт в себя и контент, и тему, и настройки. Отдельно копировать `theme/` не нужно.

---

## 4. Импорт на хостинг

1. В админке **старого** сайта: Плагины → Добавить новый → *All-in-One WP Migration* →
   установить и активировать (если ещё не сделали на шаге 2).
2. All-in-One WP Migration → **Import**.
3. Если лимит загрузки меньше размера файла — поставить дополнение
   *All-in-One WP Migration File Extension* (бесплатное, снимает лимит),
   либо поднять `upload_max_filesize` и `post_max_size` в Plesk → PHP Settings до 128M.
4. Import From → File → выбрать `.wpress` из шага 3.
5. Плагин предупредит, что перезапишет базу и файлы — это и есть замена сайта. Продолжить.
6. По окончании он попросит **сохранить постоянные ссылки два раза** — сделать.

После импорта логин и пароль администратора становятся **local-овскими: `admin` / `password`.**

---

## 5. Сразу после импорта — обязательные действия

- [ ] **Сменить пароль администратора.** Пользователи → admin → Новый пароль → длинный, из менеджера паролей.
- [ ] **Сменить e-mail администратора** на рабочий, иначе письма о восстановлении уйдут в пустоту.
- [ ] **Постоянные ссылки.** Настройки → Постоянные ссылки → структура «Название записи» → Сохранить (дважды).
- [ ] **Проверить главную.** Настройки → Чтение → «На главной странице отображать» → *Статическую страницу* → Главная.
- [ ] **Часовой пояс** — Настройки → Общие → Asia/Almaty.
- [ ] **Удалить демо-контент**: страницу «Sample Page», запись «Привет, мир!».
- [ ] **Создать учётку для школы**: Пользователи → Добавить нового → роль **Редактор**.
      Именно ею пользуется школа (см. [ADMIN.md](ADMIN.md)), администратор остаётся у разработчика.

---

## 6. HTTPS

Домен уже работает по https, но после импорта в базе останутся ссылки `http://localhost:8888`.

1. Plesk → biart.kz → **SSL/TLS Certificates** → Let's Encrypt → выпустить/продлить, включить
   *Redirect from http to https*.
2. В админке: Настройки → Общие → **Адрес WordPress** и **Адрес сайта** = `https://biart.kz`
   (без `/ru`, без слеша на конце).
3. Заменить оставшиеся ссылки в базе. Проще всего плагином *Better Search Replace*:
   найти `http://localhost:8888` → заменить на `https://biart.kz`, все таблицы,
   сначала с галочкой «тестовый прогон», потом без неё.
4. Открыть сайт, убедиться, что замок в адресной строке без предупреждений
   (нет «смешанного содержимого» — проверяется в консоли браузера).

---

## 7. Редиректы со старых адресов

Без них поисковая выдача и старые ссылки упрутся в 404.

### Вариант А — nginx (быстрее, надёжнее)

Plesk → biart.kz → **Apache & nginx Settings** → *Additional nginx directives*:

```nginx
location = /ru/ { return 301 https://biart.kz/; }
location = /kk/ { return 301 https://biart.kz/kz/; }

location = /ru/politika-konfidenczialnosti/  { return 301 https://biart.kz/privacy-policy/; }
location = /kk/politika-konfidenczialnosti/  { return 301 https://biart.kz/privacy-policy/; }

location = /ru/dogovor-publichnoj-oferty/    { return 301 https://biart.kz/dogovor-publichnoj-oferty/; }
location = /kk/dogovor-publichnoj-oferty/    { return 301 https://biart.kz/dogovor-publichnoj-oferty/; }

location = /ru/dogovor-oferty-sertifikata/   { return 301 https://biart.kz/dogovor-oferty-sertifikata/; }
location = /kk/dogovor-oferty-sertifikata/   { return 301 https://biart.kz/dogovor-oferty-sertifikata/; }

# всё остальное из языковых папок — на главную
location ^~ /ru/ { return 301 https://biart.kz/; }
location ^~ /kk/ { return 301 https://biart.kz/kz/; }
```

Нажать **Apply**, затем проверить (раздел 8).

### Вариант Б — плагин

Если доступа к nginx-директивам нет: плагин *Redirection*, вкладка «Редиректы»,
добавить те же пары «источник → цель», тип 301. Медленнее (каждый запрос идёт через PHP),
но работает.

## 8. Проверка

Прогнать все пункты, прежде чем считать замену состоявшейся.

**Адреса** (в терминале или просто в браузере):

```bash
for u in / /kz/ /dogovor-publichnoj-oferty/ /privacy-policy/ /dogovor-oferty-sertifikata/; do
  echo -n "$u -> "; curl -s -o /dev/null -w '%{http_code}\n' "https://biart.kz$u"
done
for u in /ru/ /kk/ /ru/dogovor-publichnoj-oferty/ /ru/politika-konfidenczialnosti/; do
  echo -n "$u -> "; curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "https://biart.kz$u"
done
```

Ожидаем: первые пять — `200`, вторые четыре — `301` на новые адреса.

**Глазами:**

- [ ] главная: фото на первом экране, карусель листается стрелками и свайпом, счётчик «01 / 39» меняется;
- [ ] переключатель РУС / ҚАЗ водит между `/` и `/kz/`;
- [ ] кнопки «Записаться» открывают WhatsApp с заполненным текстом;
- [ ] карта в контактах показывает метку школы;
- [ ] на телефоне: бургер-меню открывается, плавающая кнопка WhatsApp на месте;
- [ ] в подвале все четыре ссылки открываются, включая юридические страницы;
- [ ] FAQ раскрывается по клику;
- [ ] консоль браузера без красных ошибок.

**Поиск и аналитика:**

- [ ] `https://biart.kz/wp-sitemap.xml` отдаёт карту сайта (её генерирует сам WordPress; Yoast после замены не будет);
- [ ] в Google Search Console добавить новую карту сайта и удалить старую `/sitemap_index.xml`;
- [ ] если нужен Google Analytics — поставить Site Kit заново и подключить аккаунт;
- [ ] `https://biart.kz/` отдаёт `<link rel="alternate" hreflang="kk" href="https://biart.kz/kz/">` (это делает `theme/inc/seo.php`).

## 9. Откат

Если что-то пошло не так и чинить некогда:

1. Plesk → Backup Manager → бэкап из шага 2 → **Restore**. Возврат занимает несколько минут.
2. Если Plesk-бэкап не восстанавливается — поставить чистый WordPress и импортировать
   `.wpress` старого сайта (бэкап 2) тем же All-in-One WP Migration.
3. Убрать nginx-директивы из раздела 7, иначе они будут гонять старые адреса вхолостую.

## 10. Как жить дальше

**Тексты и фото** школа правит в админке — см. [ADMIN.md](ADMIN.md). Ничего перевыкладывать не нужно.

**Вёрстка и новые секции** — работа в репозитории: правки в `theme/`, проверка локально,
коммит. Чтобы доставить их на боевой сайт, есть два пути:

- *Мелкая правка стилей/шаблонов* — залить изменённые файлы `theme/` по SFTP
  в `/wp-content/themes/biart/`. Не забыть бампнуть `Version:` в `style.css`,
  иначе браузеры и кэш паттернов не увидят изменений.
- *Правка контента главной* — контент лежит в `theme/content/*.html` и попадает в базу
  только через `npm run seed`, а он работает **лишь локально**. На боевом сайте контент
  придётся либо править руками в админке, либо снова гнать полный слепок через
  All-in-One WP Migration — и тогда правки, сделанные школой, затрутся.
  Поэтому: после запуска правьте контент в админке, а файлы в репозитории
  обновляйте под изменившуюся вёрстку.

**Обновления WordPress** — только через разработчика. Тема протестирована на 7.1.

**Бэкапы** — включить автоматические в Plesk (Backup Manager → Scheduled Backups),
раз в неделю, хранить 4 копии.

## Чего на сайте пока нет

Стоит закрыть до или сразу после запуска:

- фотографии директора, кураторов и педагогов (сейчас плейсхолдеры);
- казахские версии юридических страниц — ссылки в KZ-подвале ведут на русские;
- на старом сайте были подключены Yoast и Google Site Kit: после замены их не будет,
  SEO-теги отдаёт сама тема (`theme/inc/seo.php`), аналитику нужно подключить заново.

Чек-лист по безопасности хостинга — [SECURITY.md](SECURITY.md).
