# Безопасность сайта BIART — что уже сделано и что сделать на хостинге

## Уже в теме (работает на любом хостинге, плагины не нужны)
`theme/inc/security.php`:
- Отключён XML-RPC (брутфорс, DDoS-усиление) и pingback.
- Закрыто перечисление пользователей: `?author=1`, архивы авторов, `/wp-json/wp/v2/users` для неавторизованных.
- Убраны «отпечатки» WordPress: версия ядра, RSD/wlwmanifest/shortlink/oEmbed-ссылки, `X-Pingback`.
- Комментарии отключены полностью.
- Ошибка входа обезличена («Неверный логин или пароль»).
- Заголовки на фронте: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`,
  `Content-Security-Policy` (только свой домен — у сайта нет внешних скриптов/шрифтов).
- «Пароли приложений» доступны только администратору.
- Клиент работает под ролью **Редактор**: не видит Записи/Инструменты, не может снять блокировку блоков.

## При выборе хостинга — спросить
- PHP **8.2+**, MySQL 8 / MariaDB 10.6+, HTTPS (Let's Encrypt) **бесплатно и автоматически**.
- Ежедневные **бэкапы** на стороне хостинга + возможность скачать.
- SSH и WP-CLI (нужны для обновлений при `DISALLOW_FILE_MODS`), либо хотя бы файловый менеджер.
- Лимит попыток входа / защита от брутфорса на уровне хостинга — есть ли.
- Для Казахстана: сервер в KZ или РФ/ЕС — по требованиям к персональным данным (форм нет, но админка есть).

## После переезда на хостинг — по порядку
1. **HTTPS** включить, добавить редирект http→https и HSTS
   (`Strict-Transport-Security: max-age=31536000; includeSubDomains` в `.htaccess`/nginx).
2. **wp-config.php** добавить:
   ```php
   define( 'DISALLOW_FILE_EDIT', true );   // нет редактора кода в админке
   define( 'DISALLOW_FILE_MODS', true );   // плагины/темы только через SSH или WP-CLI
   define( 'FORCE_SSL_ADMIN', true );
   define( 'WP_AUTO_UPDATE_CORE', 'minor' );
   define( 'WP_DEBUG', false );
   ```
   Соли (`AUTH_KEY` и т.д.) сгенерировать заново: https://api.wordpress.org/secret-key/1.1/salt/
3. **Аккаунты**: после импорта пароль admin = `password` — **сменить сразу** на длинный (менеджер паролей),
   переименовать `admin` в другое имя, e-mail — рабочий. Клиенту — отдельный аккаунт с ролью Редактор.
4. **Плагины-минимум** (только из каталога wordpress.org, не «nulled»):
   - `Two-Factor` — двухфакторный вход для всех аккаунтов.
   - `Limit Login Attempts Reloaded` — блокировка после N неверных паролей.
   - `UpdraftPlus` — бэкапы в Google Drive/Яндекс (если хостинг не делает): БД ежедневно, файлы еженедельно.
   - `All-in-One WP Migration` — только для переноса, после переноса удалить.
   Wordfence или Solid Security — по желанию, **один** из двух, не оба.
5. **Cloudflare (бесплатный тариф)** перед сайтом: скрывает IP сервера, WAF, защита от DDoS, кэш статики.
   Режим SSL — Full (strict).
6. **`.htaccess`/nginx**: запретить выполнение PHP в `wp-content/uploads`, закрыть `xmlrpc.php`, `wp-config.php`,
   `readme.html`, `license.txt`, `.git`.
7. **Обновления**: авто — минорные ядра и плагины; раз в месяц вручную проверить крупные обновления
   (сначала на локальной копии `npm run start`, потом на проде).
8. **Проверка восстановления** из бэкапа — раз в квартал, на локальной копии.
9. **Мониторинг**: UptimeRobot (бесплатно) — уведомление в Telegram, если сайт упал.
10. **Шрифты**: перед запуском купить веб-лицензию CoFo Raffine (сейчас используется десктопная).

## Что НЕ нужно (и почему)
- Плагины «безопасности всё-в-одном» с десятками опций — дублируют то, что уже сделано в теме, и замедляют сайт.
- Смена префикса таблиц и «скрытие» wp-login — низкая польза, ломает плагины; 2FA + лимит попыток надёжнее.
- Капча — форм на сайте нет, защищать нечего.

## Быстрая самопроверка после деплоя
```bash
curl -I https://домен/                         # заголовки: HSTS, CSP, X-Frame-Options
curl -X POST https://домен/xmlrpc.php          # 403
curl https://домен/wp-json/wp/v2/users         # 401
curl -I "https://домен/?author=1"              # 301 на главную
```
