# CLAUDE.md — правила сборки сайта на WordPress нейросетью (универсальные)

> Положи этот файл в КОРЕНЬ проекта под именем `CLAUDE.md`. Claude Code читает его сам перед работой —
> и собирает сайт правильно с первого раза, без типичных граблей WordPress.
> Это «память проекта»: один раз положил → ИИ не повторяет ошибки и не жжёт токены.

## ЧТО ДЕЛАЕМ
Блочная тема WordPress, собранная КОДОМ по референсу. Главное требование: сайт должен **редактироваться клиентом
через админку** (нативные блоки), а не быть «мёртвой картинкой». Стек: `wp-env` + Docker локально, тема в `./theme`,
сайт `http://localhost:8888` (admin/password).

## 🔴 ЖЕЛЕЗНЫЕ ПРАВИЛА (нарушишь — будут грабли)

1. **Только НАТИВНЫЕ блоки**: `wp:group`, `wp:columns/column`, `wp:heading`, `wp:paragraph`, `wp:image`, `wp:buttons/button`.
   **НИКОГДА не используй `wp:html` (Custom HTML) для дизайна** — Gutenberg рендерит его в sandbox-iframe, стили темы туда
   не попадают → в редакторе каша (хотя на фронте ок). Весь дизайн — родными блоками.

2. **Стили грузи и в редактор**: в functions.php `add_editor_style(['<google-fonts-url>', 'style.css'])`.
   Иначе канвас Site Editor будет без стилей темы.

3. **Сброс кэша CSS**: версия style.css = `filemtime(get_stylesheet_directory().'/style.css')` в `wp_enqueue_style`.
   Со статичной версией браузер кэширует файл, и новые CSS-правила не подхватываются.

4. **Стилизация по классам.** У групп ставь `"layout":{"type":"default"}` — тогда твой CSS (flex/grid) рулит,
   а WordPress не навязывает constrained-обёртку. Обнуляй дефолтные `margin` у блоков-обёрток
   (`.nav p{margin:0}`, `figure{margin:0}` и т.п.).

5. **Все размеры/отступы/положения — через CSS-переменные** в `:root` (десктоп) и `--m-*` в `@media(max-width:781px)`
   (мобилка; на этой ширине колонки WordPress стекаются). Для подгонки удобно сделать временную плавающую DevPanel
   (ползунки → `style.setProperty` на :root), потом зашить значения и панель удалить.

6. **Картинки/ассеты** — файлами в `theme/assets/`. Вставляй `wp:image` с **корне-относительным** путём
   `/wp-content/themes/<тема>/assets/...` — портативно (работает и на боевом домене).

7. **НЕ сохраняй правки шаблона в Site Editor** во время разработки — это создаёт копию в БД (`wp_template`),
   которая ПЕРЕКРЫВАЕТ файл темы. Симптом: меняешь файл — на фронте ничего. Фикс: удалить запись
   (`wp post delete <ID> --force`, post_type=wp_template) или «Очистить настройки». Правь ФАЙЛЫ.

8. **Свои отступы внутри групп бей специфичностью.** WordPress даёт `:root :where(.is-layout-flow) > *{margin-block:0}`
   (специфичность 0,1,0, идёт позже) — он перебивает твои `.class{margin}`. Решение: повысь специфичность селектора
   (`.section .item{...}`), либо добавь `:root` к своему правилу.

9. **Паттерны** (фирменные блоки для клиента): `theme/patterns/*.php` с шапкой `Title/Slug/Categories`.
   ВАЖНО: список паттернов кэшируется по **версии темы** — после добавления **бампни `Version:`** в style.css
   (+ `wp_clean_themes_cache()`). Категорию задай `register_block_pattern_category`.

10. **Видео/гиф**: на обёртке задай `aspect-ratio` (иначе бокс схлопывается в 0, пока медиа грузится) + `object-fit:cover`.
    Для автоплея — **локальный файл** + `autoplay loop muted playsinline` (remote/тяжёлое не автоплеится надёжно).

11. **WordPress обновляй** через `.wp-env.json` (`core` + `wp-env start --update`), НЕ кнопкой в админке (откатит).

## АРХИТЕКТУРА ШАБЛОНОВ
- `templates/front-page.html` → `wp:post-content` (главная = Страница, чтобы её правил клиент).
- `templates/page.html` → `wp:post-content` — **ОБЯЗАТЕЛЕН.** Без него любая обычная страница показывает `index.html`
  (запасной шаблон), а не свой контент.
- Контент лендинга держи в **Странице**, не в шаблоне: клиент-Редактор правит простым редактором
  (Site Editor доступен только администратору).

## ОТДАЧА КЛИЕНТУ (чтобы менял, но не ломал)
- На секции верхнего уровня — `"templateLock":"contentOnly"` → клиент правит только текст/медиа, структуру не трогает.
- Запрет разлочки: `canLockBlocks=false` для не-админов (фильтр `block_editor_settings_all`).
- Клиент = роль **Editor**; уберни лишнее из меню админки (`admin_menu`: Записи/Комментарии/Инструменты).

## ДЕПЛОЙ (кратко)
- Перенос на хостинг — плагином All-in-One WP Migration (экспорт локально → импорт на боевой, обходит лимиты).
- После импорта: сбросить Постоянные ссылки, **сменить пароль admin** (станет admin/password!), включить HTTPS
  (Let's Encrypt + Really Simple SSL). Проверить, что `page.html` есть и REST API открыт (для MCP).

## РАБОЧИЙ ПОРЯДОК
1. Поднять wp-env, скелет темы, активировать.
2. Свёрстать ПЕРВУЮ секцию нативными блоками по правилам → проверить на фронте И в редакторе.
3. Остальные секции по тому же образцу.
4. Тюнинг переменными → зашить.
5. Отдача клиенту (роль + contentOnly) → паттерны → MCP → деплой.
